# Proxy / TUN operation

The standard installation prepares both modes automatically. Start it with
`docker compose up -d`, open Settings → **Режим подключения**, and choose
**Прокси / TUN**. There is no gateway deployment profile, required JSON file,
separate environment file, or manual Mihomo credential setup. Proxy is the default.
First TUN setup asks for Local DNS in the application; valid changes apply
immediately, and text fields save on blur. Public upstream/bootstrap resolvers,
fake-IP and TUN defaults are generated by Submerge. TUN keeps HTTP/SOCKS available.

## Deployment and upgrades

Use Linux with `/dev/net/tun` and Docker Compose >=2.36. Docker Desktop supports
an isolated container-network test, not physical-LAN gateway acceptance.
The standard Compose already provides the device, engine-only NET_ADMIN,
forwarding guard, stable namespace, volume initialization and TCP/UDP DNS port.
Internal setup services run automatically. The panel stays at loopback :3000,
HTTP/SOCKS at :7890 and DNS at :1053. The engine API is not published.
Volume initialization migrates known SQLite/config/HWID/canonical-rule files from
earlier root deployments; published private-list ownership is never changed.
The config directory allows traversal for an existing host fetcher publishing
below it; database/rule directories and credential files remain private.
The decoder's dedicated group reads only the HWID mirror; it cannot read engine
credentials. Host-run development keeps its existing HWID sharing behavior.

Existing installations must receive the updated complete Compose once. Updating
only the application image cannot grant missing Docker permissions or ports.
Keep the existing SQLite/config/rule mounts when adapting a custom deployment.
Bootstrap generates a strong engine credential, retains existing strong credentials,
and uses the durable rotation journal to recover interrupted updates. Later
environment edits do not replace confirmed credentials. An old managed Proxy
config is regenerated from its database; accepted TUN configurations are retained.
ADMIN_PASSWORD and COOKIE_SECURE retain their existing deployment meaning;
public deployments need password + TLS, and TUN requires a strong admin password.
Proxy on trusted localhost still works with no environment file.

For a reverse proxy on the Compose network, use `submerge:3000` (an alias on the
stable namespace). Docker-discovery labels/network attachments belong to
`submerge-network`, the service owning that address. For a host reverse proxy,
keep the existing `127.0.0.1:3000` endpoint.

## Private lists

The existing fetch service keeps its deploy key and publishes the list directory.
`mihomo/private-lists` is the default read-only mount; an existing published path
can be attached with PRIVATE_LISTS_DIR during installation. No lists are required
for ordinary setup. When present, notblocked.txt and custom.txt are offered in
Settings automatically. UID 999 must be able to traverse/read the published files.
Never mount the deploy key. DIRECT entries retain exact full domain names.
Managed writable custom.txt remains in the separate domain-rules mount.
DOMAIN_RULES_MODE stays report until its existing apply installation is complete.

## Optional parallel test

The test override provides independent project volumes, network namespace,
TUN/routing tables and LAN subnet, without modifying the running installation:

```bash
docker compose -p submerge-test -f docker-compose.yml -f docker-compose.test.yml up -d
```

The test panel is at :13000, HTTP/SOCKS at :17890 and DNS at :11053. Select the
mode in this instance's Settings. Normal upgrades need only `docker compose up -d`;
mode changes never require Compose edits. For PR testing, set SUBMERGE_IMAGE to
the published PR image once. Remove the test with the same command plus `down`;
omit `-v` to retain its settings.

## Network clients and acceptance

Server-side TUN captures packets reaching its own namespace. To route physical
LAN clients through it, choose a reachable LAN attachment once. The optional
`docker-compose.gateway.lan.yml` macvlan override retains this advanced deployment
choice: provide the host LAN interface, an unused LAN IP, subnet and router.
Use the displayed gateway/DNS addresses only when the UI identifies them as LAN
reachable. Client routes and AdGuard forwarding are separate network changes;
Submerge does not silently replace host routes, DHCP or the existing AdGuard setup.
The namespace has IPv6 disabled. Isolate or disable IPv6 on opted-in test clients
until a separate IPv6 migration is accepted; their existing IPv6 default router
otherwise remains a route around the tested IPv4 gateway.
Public/bootstrap DNS never uses system. Local names use the separate configured
local resolver, which must not forward those zones back into Submerge.

Check readiness in Settings. It tests the active configuration, TUN, TCP/UDP DNS,
fresh public/local resolution, loaded lists, default routing and VPN pool.
No VPN nodes means internet default traffic is rejected. Invalid configuration
keeps the last accepted engine file and shows an explicit activation failure.
Liveness (/healthz) remains separate from operational readiness.

## Developer verification

```bash
docker build -t submerge-gateway:verify .
GATEWAY_INTEGRATION=1 pnpm -F @submerge/server test src/modules/gateway/gateway.integration.test.ts
```

These opt-in isolated tests use the standard Compose and real Linux Mihomo,
exercise default localhost startup, protected mode transitions, persistence,
DNS/TUN, exact-domain lists, empty pools, invalid reloads, credential recovery,
engine restart and blocked raw forwarding after engine death. They clean up their
temporary resources. Physical LAN and a real VPN subscription need separate
acceptance on the selected test client.
